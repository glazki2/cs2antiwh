# План: серверный анти-WH плагин для CS2 (аналог CS2FOW)

> **Статус (0.4.0).** План реализован не с нуля, а на базе
> [CS2FOW Community Edition](https://gitlab.com/Artemon0/cs2fow-ce): там уже есть бейк карт в
> BVH8, фоновый расчёт видимости, fail-open и защита от краша при смерти скрытого игрока.
> Что доработано в этом репозитории — в [README.md](README.md) и [CHANGELOG.md](CHANGELOG.md).
> Ниже — исходный план, оставлен для истории.


**Язык:** C++20 (нативный плагин Metamod:Source 2.x), без C#.
**Рабочее имя:** `AntiWH`, префикс cvar/команд — `awh_`.
**Главное требование:** плагин не должен крашить ни сервер, ни клиент. При любой неясности
он показывает всех игроков (fail-open), а не прячет лишнее.

---

## 0. Коротко

1. Сервер перестаёт отправлять клиенту данные о враге (pawn + его оружие), пока враг
   полностью закрыт статической геометрией карты или смоком. Если данных нет, WH нечего
   рисовать.
2. Геометрия карты заранее «запекается» из VPK в BVH. Лучи считаются в **фоновом потоке**
   по этой BVH, без вызова движка.
3. Хук `CheckTransmit` ничего не считает. Он только читает готовую маску видимости и
   снимает биты у скрытых врагов.
4. Защиту от крашей переносим из рабочих плагинов: игрок, умирающий в этот тик, всегда
   передаётся; сущности храним по handle, а не по индексу; наблюдатели, GOTV и
   собственный pawn никогда не прячутся. При любом сбое срабатывает fail-open.

## 2. Почему C++, а не другой язык

- `hl2sdk` и SourceHook (система хуков Metamod) требуют C++ ABI и C++-классов, так что
  прослойка на C++ нужна при любом выборе языка.
- Горячий путь (≈64 тика/с, до 64×64 пар игроков, десятки тысяч лучей за тик) не
  переносит пауз GC и интерпретатора. Lua, JS и Python через Plugify здесь не подходят.
- Все рабочие референсы (CS2FOW, CS2AC, CS2Fixes, cs2kz) написаны на C++, поэтому их
  заголовки и паттерны можно использовать напрямую.
- Возможная альтернатива: ядро (парсер карт, BVH, лучи) на Rust со статической линковкой
  через C ABI. Это даёт безопасность памяти при разборе недоверенных workshop-файлов, но
  добавляет второй тулчейн. Рекомендация: начать на C++ и закрыть этот риск
  фаззингом и санитайзерами (раздел 12).

## 3. Архитектура

```
             ┌───────────────────────── офлайн / фоновый поток ─────────────────────────┐
 map .vpk ──►│ VPK v2 → ресурс world_physics → KV3 → треугольники (фильтр по атрибутам) │──► cache/<map>_<hash>.awhbvh
             └─────────────────────────────────────────────────────────────────────────┘                 │
                                                                                                          ▼
 GameFrame (post, главный поток)                  Рабочий поток (1..N)                           BVH в памяти (read-only)
 ─ снимок ≤64 игроков в POD-структуры    ──►   ─ лучи viewer→target по BVH + смоки   ──►   VisResult (uint64-маска на зрителя)
   (позиция глаз, AABB, скорость, пинг,           ─ lookahead, гистерезис                      публикуется атомарно (triple buffer)
    команда, lifeState, observer-цель)            ─ никаких вызовов движка                                  │
 ─ детект смерти в этот тик → override                                                                      ▼
                                                                                 CheckTransmit (post-hook): только чтение маски,
                                                                                 снимаем биты pawn + оружия у скрытых врагов
```

Принципы:
- **Ядро без движка.** Модули `geo/`, `bake/`, `vis/` не подключают `hl2sdk` и работают с
  простыми структурами (`PlayerSnapshot`, `Ray`, `Triangle`). Их можно тестировать,
  фаззить и гонять в отдельном потоке, не трогая память движка.
- **Между потоками передаются только копии данных.** Указатели на сущности живут в
  пределах одного вызова на главном потоке и между тиками не кешируются. Сущности
  разрешаются через `CHandle` (индекс + serial).
- **`CheckTransmit` делает минимум работы:** O(клиенты × враги), без аллокаций, без
  блокировок и без лучей. Хук читает неизменяемый опубликованный результат, поэтому он
  потокобезопасен, даже если движок вызывает его параллельно.
- **Хуки ставятся только через SourceHook на виртуальные методы интерфейсов**
  (`ISource2Server::GameFrame`, `ISource2GameEntities::CheckTransmit`). Индексы vtable
  берутся из `hl2sdk`. Сигнатур по возможности **ноль**: поля сущностей читаем через
  SchemaSystem, как в CS2Fixes и CS2AC, а не по захардкоженным офсетам. Меньше сигнатур
  значит меньше крашей после патчей CS2.

## 4. Главный принцип: fail-open

Спрятать видимого врага хуже, чем показать скрытого: невидимый противник, который
стреляет в игрока, ломает игру сильнее любого WH. Поэтому во всех сомнительных случаях
**показываем всех**:

| Ситуация | Поведение |
|---|---|
| `awh_enable 0` | Хуки стоят, но ничего не снимают |
| Для текущей карты нет BVH (идёт бейк, бейк не удался, файл битый) | Показываем всех, в лог пишется причина |
| Результат рабочего потока старше `awh_fail_open_ms` (по умолчанию 200 мс) | Показываем всех, пока поток не догонит |
| Не найдено schema-поле, интерфейс или vtable при загрузке | Плагин загружен, но выключен; в лог пишется, что именно не найдено |
| Санити-проверка в хуке не прошла (`m_nPlayerSlot` вне `[0,64)`, `nullptr` в битсетах) | Автовыключение до смены карты, сообщение в лог |
| Исключение или ошибка в рабочем потоке | Ловим на верхнем уровне потока, выключаемся (fail-open), пишем в лог |
| Рабочий поток не успевает за тиком | Деградация: реже пересчитываем дальние и неподвижные пары, пускаем меньше лучей, затем fail-open |

## 5. Правила, которые защищают КЛИЕНТ от краша

Все правила проверяются на этапе 1 (раздел 11) на **реальных клиентах**, не на ботах.

1. **Умирающий pawn передаётся в тот же тик.** В `GameFrame` (post) каждый тик
   опрашиваем `m_lifeState` и `m_iHealth` у pawn (без сигнатуры на `player_death`). Если
   игрок умер или умирает в этом тике, ставим override «всегда передавать» (обход
   `CopyExistingEntity: missing client entity`, Valve #3732). Мёртвые pawn не прячем
   вообще: рэгдолл в CS2 создаётся на клиенте из pawn.
2. **Прячем только живые вражеские `CCSPlayerPawn`**, как в CS2Fixes. Контроллеры
   (`CCSPlayerController`), gamerules, team-сущности, мир, брошенное оружие и снаряды не
   трогаем.
3. **Оружие прячем вместе с владельцем.** Сюда входят `m_pWeaponServices->m_hMyWeapons`,
   `m_hActiveWeapon` и дочерние сущности по иерархии scene node. Иначе оружие без
   владельца либо «висит в воздухе» (утечка для ESP), либо ломает клиент. При смерти или
   раскрытии pawn возвращаем всё сразу.
4. **Паттерн CS2Fixes:** при скрытии снимаем бит в `m_pTransmitEntity` и ставим в
   `m_pTransmitNonPlayers`, чтобы клиент получил корректное удаление.
   `unionTransmitEdicts` не трогаем.
5. **Биты в `m_pTransmitEntity` только снимаем, никогда не добавляем.** Решение о
   передаче остаётся за движком (PVS); мы лишь сужаем его.
6. **Никогда не прячем:**
   - собственный pawn зрителя и всё, чем он владеет;
   - тиммейтов (по умолчанию; в FFA/DM «враг» — любой, кроме себя);
   - цель наблюдения (observer target) у наблюдателя;
   - убийцу для жертвы в течение `awh_killer_reveal_ms` после смерти (deathcam и
     freezecam смотрят на убийцу);
   - кого угодно для GOTV/HLTV-клиента (`m_bIsHLTV`) и для свободной камеры
     (`awh_spectators`, по умолчанию «все видят всех»).
7. **Мёртвый игрок, наблюдающий за тиммейтом,** получает маску видимости того, за кем
   наблюдает, а сама цель передаётся всегда.
8. **Handle вместо индекса.** Любые списки «скрытых», «умирающих» или «переопределённых»
   хранят `CEntityHandle`. Запись удаляется, как только индекс указывает на другую
   сущность (урок jRandomSkills: индекс освобождается через ~0.1 с и переиспользуется).
9. **Льготные окна:** в тик спавна, в первые `awh_spawn_grace_ms` после спавна или
   коннекта и при `m_bFullUpdate` не прячем никого.

## 6. Правила, которые защищают СЕРВЕР от краша

- Каждое разыменование проверяется на `nullptr`. Индексы проверяются по диапазонам:
  слот `< 64`, entindex `< 16384`.
- В хуке `CheckTransmit` нет аллокаций, исключений, блокировок и логирования в горячем
  пути: только счётчики.
- Все schema-поля резолвятся при загрузке. Если хотя бы одно не найдено, плагин
  выключается целиком.
- `Unload`, `LevelShutdown` и `meta unload` выполняются по одной схеме: выставить флаг
  выключения, снять все хуки, выставить флаг отмены бейка, `join` рабочего потока и
  потока бейка, освободить BVH. Бейк проверяет флаг отмены каждые N треугольников, чтобы
  `join` не зависал.
- Недоверенные входные данные (VPK и ресурсы workshop-карт) парсятся с проверкой каждой
  длины и смещения. Парсер фаззится (раздел 12). При ошибке бейк отменяется, работает
  fail-open.
- Сборка Linux идёт в Docker-образе Steam Runtime 3 (sniper), как у CS2AC: ABI и glibc
  совпадают с сервером. Внешних `.so`/`.dll` нет, всё линкуется статически.
- Совместимость с другими плагинами, хукающими `CheckTransmit` (CS2Fixes hide,
  CounterStrikeSharp `OnCheckTransmit`): мы только снимаем биты у своих целей, поэтому
  порядок загрузки не должен ломать ни нас, ни их. Это проверяется отдельным тестом.

## 7. Алгоритм видимости

Для каждой пары (зритель V, живой враг T), где V — реальный клиент.

**Быстрые исходы:**
- Если расстояние меньше `awh_close_range` (≈ 200 ед.), T видим: вблизи прятать опасно
  (углы, прыжки, ножи).
- Если маску пары уже считали в этом цикле, берём результат из кеша. Приоритет пересчёта
  — у пар, которые движутся или находятся близко.

**Точки зрителя (откуда смотрим).** Это текущая позиция глаз плюс то, где глаза могут
оказаться за время lookahead:
- `eye = origin + m_vecViewOffset`;
- `eye + v·t` (экстраполяция по скорости);
- `eye ± side·s`, где `s = max(|v|, 250)·t`: боковые точки перпендикулярно лучу
  (пик за угол);
- `eye + up·jump(t)`: прыжок (высота прыжка ≈ 57 ед.);
- `t = clamp(ping + interp(≈2 тика) + awh_lookahead_ms, 60, 300) мс`. Пинг берём из
  `m_iPing` контроллера.

**Точки цели (куда смотрим).** Для цели используем консервативную форму:
- В MVP: AABB стоя (32×32×72) даже для присевшего врага, потому что он может встать.
  Точки: голова, грудь, таз, ноги, левый и правый края плеч и те же точки, сдвинутые на
  `v·t`.
- Позже (этап 7): капсулы хитбоксов по костям, как в CS2FOW. Это уменьшает число ложно
  видимых целей.

**Тест:** отрезок из точки зрителя в точку цели проверяется на пересечение с BVH
(any-hit, можно остановиться на первом пересечении) и со смоками. **Хватает одного
свободного луча**, чтобы цель считалась видимой. Лучи идут в порядке «последний
успешный луч первым», что использует временную когерентность. В худшем случае на пару
приходится ≈5×10 = 50 лучей.

**Гистерезис:**
- Видимый → скрытый: только после `awh_hold_visible_ms` (≈200 мс) без единого свободного
  луча.
- Скрытый → видимый: сразу.

**Смоки (этап 4):**
- Активный смок — `smokegrenade_projectile` с `m_bDidSmokeEffect` и
  `m_vSmokeDetonationPos`.
- MVP: сфера радиусом меньше визуального (≈0.8×). Луч считается заблокированным, если
  проходит внутри сферы дольше `awh_smoke_min_len`.
- Во время расширения и рассеивания смок считается прозрачным. После взрыва HE или
  молотова рядом со смоком он считается прозрачным `awh_smoke_he_ms` миллисекунд (дыры в
  воксельном смоке).
- При любой неопределённости смок прозрачен (fail-open).

**Что НЕ считается преградой (MVP):**
- двери, `func_breakable`, динамические пропсы (их нет в статической геометрии);
- стекло, решётки, сетки, заборы;
- `playerclip`, `npcclip`, `sky`, триггеры: они блокируют движение, но не взгляд;
- при сомнении — прозрачно.

## 8. Бейк карт

1. **Вход.** Файл `game/csgo/maps/<map>.vpk` или VPK workshop-карты. Формат VPK v2:
   директория плюс архивы.
2. **Ресурс физики мира.** Берём `maps/<map>/world_physics.vmdl_c` или `.vphys_c`
   (`PhysAggregateData`). Ресурс Source 2 состоит из блоков, данные лежат в бинарном KV3
   (сжатие LZ4 или ZSTD). Как справочник формата используем исходники ValveResourceFormat,
   код не копируем.
3. **Геометрия.** Из частей и форм берём меши (вершины и треугольники) и выпуклые hull
   (грани триангулируем). Сферы и капсулы в мире встречаются редко, их можно
   аппроксимировать.
4. **Фильтр.** Оставляем только непрозрачное: смотрим атрибуты коллизии
   (`m_collisionAttributes`, interaction layers) и surface properties. Исключаем clip,
   sky, trigger, glass, grate, chainlink. Неизвестный атрибут трактуем как прозрачный.
5. **BVH.** Header-only библиотека без внешних зависимостей: `tinybvh` (MIT, есть
   BVH4/BVH8 и SIMD-обход) или `madmann91/bvh` (MIT, C++20). Сборка по SAH.
6. **Кеш.** Файл `addons/antiwh/cache/<map>_<hash>.awhbvh`. В заголовке: magic, версия
   формата, имя карты, хеш VPK (размер, mtime, CRC), число треугольников. Кеш
   инвалидируется при обновлении карты.
7. **Когда запекается:**
   - офлайн CLI `awh-bake <путь к vpk|папке>` на машине разработчика, для стандартных
     карт готовые кеши кладутся в релиз;
   - автоматически в фоновом потоке при загрузке карты без кеша (workshop). Пока бейк
     идёт, работает fail-open;
   - админ-команда `awh_bake`.
8. **Сверка с движком (только в debug).** Раз в секунду пускаем N случайных лучей и
   через BVH, и через движковый `TraceShape` (как в CS2AC, на главном потоке), затем
   логируем процент расхождений. Цель — меньше 1 %, и все расхождения должны быть в
   сторону «видим».

Память и время бейка на реальных картах замеряем на этапе 2. Если BVH получается слишком
большой, квантуем вершины и упрощаем меш.

## 11. Этапы

Каждый этап заканчивается сборкой на Linux и Windows и прогоном чек-листа из раздела 12.

**Этап 0. Каркас.**
Пустой Metamod-плагин (AMBuild, сабмодули, CI), `Load`/`Unload`, cvars, `awh_status`.
*Готово, когда* плагин 100 раз подряд переживает `meta load`/`meta unload` и
`changelevel` без утечек (ASan-сборка на Linux).

**Этап 1. Прототип скрытия «по расстоянию», без лучей.**
Хук `CheckTransmit` и все правила раздела 5, но «скрыт» пока означает «дальше X
единиц». Здесь **проверяется безопасность протокола передачи** до того, как появится
сложная математика.
*Готово, когда* весь чек-лист крашей из раздела 12 пройден на 2+ реальных клиентах.

**Этап 2. Бейк и BVH.**
`bake/` и `geo/`, CLI `awh-bake`, кеш, unit-тесты, фаззинг парсеров, сверка с движковым
`TraceShape` в debug.
*Готово, когда* запекаются все карты Active Duty и одна workshop-карта, а расхождение с
движком меньше 1 % и только в сторону «видим».

**Этап 3. Видимость в рабочем потоке.**
Снимок в `GameFrame`, triple buffer, точки, lookahead, гистерезис, fail-open по
свежести.
*Готово, когда* 5v5 проходит без «поп-ина» (враг не появляется из воздуха) при
искусственном пинге 0/80/150 мс и на пиках на полной скорости и в прыжке.

**Этап 4. Смоки и HE.**
*Готово, когда* враг за смоком скрыт, а после HE через дыру виден без задержки.

**Этап 5. Производительность и нагрузка.**
Метрики, деградация под нагрузкой, 32v32 на ботах (цели) плюс реальные клиенты
(зрители), 3+ часа без рестарта.
*Цели:* `CheckTransmit` ≤ 20 мкс на тик при 32 клиентах, цикл рабочего потока ≤ 3 мс на
одном ядре при 32v32.

**Этап 6. Workshop, релиз, документация.**
Автобейк в фоне, упаковка (`addons/metamod/antiwh.vdf`, бинарники, cfg, готовые кеши
стандартных карт), README для админов, чек-лист обновления после патча CS2.

**Этап 7 (по желанию).**
Капсулы хитбоксов по костям, двери как динамические окклюдеры, исследование утечек
через звуковые события.

## 12. Тестирование

**Автотесты (CI):**
- unit-тесты `geo/`, `bake/`, `vis/` (луч↔треугольник, BVH против brute force, точки,
  гистерезис);
- ASan и UBSan на Linux;
- libFuzzer на парсерах VPK, resource и KV3 с корпусом из реальных и обрезанных или
  испорченных файлов.

**Чек-лист крашей (реальные клиенты, минимум 2 аккаунта):**
- [ ] Скрытый враг умирает рядом: пуля, нож, HE, молотов, падение, бомба, `kill`, тимкилл.
- [ ] Скрытый враг отключается или кикается (`kickid`, `bot_kick`) во время скрытия.
- [ ] Скрытый враг бросает гранату, подбирает или выбрасывает оружие, переключает оружие.
- [ ] Скрытый носитель C4; сброс и подбор бомбы; установка и дефьюз.
- [ ] Смерть зрителя: deathcam и freezecam на скрытого убийцу.
- [ ] Наблюдатель быстро переключает цели; свободная камера; команда spectator.
- [ ] `tv_enable 1` плюс запись демо; просмотр демо без ошибок.
- [ ] `mp_restartgame`, конец раунда, конец карты, `changelevel` посреди бейка.
- [ ] Полное обновление клиента (реконнект, `cl_fullupdate` при `sv_cheats 1`).
- [ ] `meta unload` и `meta load` посреди раунда.
- [ ] Битый или удалённый кеш; workshop-карта без `world_physics`.
- [ ] Гибернация сервера (пустой сервер), затем вход игрока.
- [ ] Одновременно с CS2Fixes (hide) и с CounterStrikeSharp-плагином, который использует
      `OnCheckTransmit`.

**Проверка на «поп-ин»:**
- искусственная задержка на сервере (`tc qdisc … netem delay 80ms` на Linux, clumsy на
  Windows);
- запись демо и покадровый просмотр пиков на Dust2, Mirage, Inferno, Nuke (много
  уровней), Vertigo, Ancient, Anubis.

## 13. Ограничения (что плагин НЕ закрывает)

- **Звуки.** Шаги и выстрелы игрок должен слышать, так что «sound ESP» останется.
- **Граница видимости.** Враги у самой кромки видимости (в пределах lookahead ≈ 100–300
  мс) передаются заранее, и WH их покажет. Это цена отсутствия поп-ина.
- **Прозрачные преграды.** Враги за дверями, стеклом, решётками и динамическими
  пропсами передаются.
- **Аимбот** по видимым целям не блокируется. Для этого нужен поведенческий античит
  (например CS2AC).
- **Только свои серверы.** Работает на community и dedicated серверах с Metamod, в
  MM/Premier не применим.

## 14. Риски

| Риск | Смягчение |
|---|---|
| Патч CS2 меняет vtable или раскладку `CCheckTransmitInfo` | Минимум сигнатур; `static_assert` на размер; санити-проверки в рантайме с автовыключением; CI собирает против свежего `hl2sdk` |
| Движок начинает вызывать `CheckTransmit` из нескольких потоков | Хук только читает неизменяемый результат; разделяемого изменяемого состояния нет |
| Ложное скрытие видимого врага | Fail-open везде, консервативные точки, гистерезис, сверка с движковым трейсом |
| Нагрузка на CPU при 64 слотах | Рабочий поток, early-exit по лучам, приоритизация пар, деградация, затем fail-open |
| Новые версии формата карт | Версионирование кеша, фаззинг, при ошибке бейка работает fail-open |
