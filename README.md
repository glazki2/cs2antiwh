# cs2glaz — анти-WH для CS2

Серверный плагин против wallhack для Counter-Strike 2. Если враг полностью закрыт стеной
(а в полном режиме — ещё и смоком), сервер просто не отправляет игроку данные об этом враге.
Чит не может нарисовать то, чего клиент не получил. Игрокам ничего ставить не нужно.

- Язык: **C++** (плагин Metamod:Source). C# и .NET не используются нигде — ни в плагине,
  ни в утилите подготовки карт.
- Основа: открытый плагин под лицензией MIT (Community
  Edition 0.3.8), доработанный в этом репозитории до версии **0.5.1**. Исходное уведомление
  об авторских правах сохранено в [LICENSE](LICENSE), как того требует лицензия.
- Принцип безопасности — **fail-open**: при любой неясности плагин показывает всех,
  а не прячет лишнее.

## Что изменено относительно исходного плагина

| Проблема в исходной версии | Что сделано |
| --- | --- |
| Metamod с 8 сентября 2026 убрал SourceHook и не загружает старые плагины | Хуки переписаны на KHook (Metamod API 18) |
| Собран на старом HL2SDK; в сентябрьском обновлении CS2 поменялись ConVar, IFileSystem, CGlobalVars | Сборка на свежих HL2SDK/Metamod |
| gamedata подходит только к CS2 1.41.7.4, на текущей версии плагин просто выключается | **Ограниченный режим**: на неизвестной сборке CS2 работает защита стенами без приватных адресов |
| Для подготовки карт запускался ValveResourceFormat — программа на C#/.NET | Свой C++-читатель физики карт (KV3 + LZ4 + Zstandard), .NET удалён полностью |
| Автообновление скачивало бинарники из репозитория исходного автора | Выключено по умолчанию; если включить — смотрит только релизы этого репозитория |

Подробности — в [CHANGELOG.md](CHANGELOG.md).

> **CS2 1.41.8 (сентябрь 2026).** В этой версии Valve поменяла механизм отправки (исчезла
> настройка `sv_enable_donttransmit`), и старый способ скрытия из CE сам заставлял сервер
> отправлять врага: второй служебный список теперь означает «отправлять». До версии 0.5.1
> враг за стеной приходил в игру вживую. С 0.5.2 плагин только снимает врага с отправки
> (в обоих списках `CheckTransmit`), и на проверке с ВХ враги, которых игрок ещё не видел, за
> стенами не видны. Врага, которого уже видели, CS2 продолжала сообщать через радар
> (около 30 секунд). С 0.5.4 плагин убирает из радара врагов, которых сейчас не видит
> никто из команды игрока (`cs2glaz_radar_filter`, включён по умолчанию).

## Два режима защиты

`cs2glaz_status` в строке `Game build:` показывает, какой режим работает.

| | Полный режим | Ограниченный режим (по умолчанию на текущем CS2) |
| --- | --- | --- |
| Когда | Бинарник сервера совпадает с проверенной gamedata | Любая другая сборка CS2 |
| Стены | Да | Да |
| Смоки и дыры от HE | Да | Да, если смещения смока подтвердились на первом живом смоке карты (иначе за смоком враг виден) |
| Форма тела врага | 19 анимированных капсул хитбоксов | 9 вертикальных капсул, гарантированно покрывающих хитбокс игрока |
| Приватные функции и адреса из gamedata | Используются | **Не используются** |

Ограниченный режим прячет немного реже, чем полный, потому что его форма тела крупнее.
Смоки он включает, только когда проверит смещения смока на первом живом смоке после запуска
(проверка идёт каждые 0,1 с с момента появления облака и обычно проходит раньше, чем облако
становится непрозрачным) через защищённое чтение памяти: центр облака должен совпасть с точкой взрыва смока, время и плотности облака
должны быть правдоподобны. Смещение облака сначала сдвигается вместе с публичными полями
схемы вокруг него (`m_fllastSimulationTime` … `m_bExplodeFromInferno`), если размер блока
между ними не изменился: так CS2 1.41.8 (+224 байта) подхватывается сам. Если и это не
подошло, плагин ищет смещение рядом и принимает его, только если оно единственное. Результат
виден в строке `Smoke:` в `cs2glaz_status`; каждая неудачная проверка пишет в консоль причину
(`smoke check N failed …`) и подробности в `addons/cs2glaz/logs/smoke_layout.txt` — пришлите
этот файл, если смок так и не включился. HE, взорванная в уже стоящем смоке, открывает в нём канал радиусом
180 юнитов на 3 секунды (`cs2glaz_he_clear_radius_units`, `cs2glaz_he_clear_seconds`): враг
за этим местом снова виден. Взрывы плагин узнаёт по событию `hegrenade_detonate`, а без него —
по тику взрыва HE-гранаты (`m_nExplodeEffectTickBegin`): сама граната живёт ещё несколько
секунд после взрыва, поэтому ждать её исчезновения нельзя. Строка `HE:` в `cs2glaz_status` показывает, сколько взрывов
он увидел на карте и когда был последний.
Зато он не зависит от адресов, которые ломаются при каждом патче CS2. Перед включением он
проверяет, что система сущностей найдена правильно. Если структура данных `CheckTransmit`
выглядит подозрительно, плагин выключает фильтрацию до смены карты.

Выключить ограниченный режим можно командой `cs2glaz_limited_mode 0`. Тогда на неизвестной
сборке CS2 плагин ничего не прячет, как было в оригинале.

## Требования

- Выделенный сервер CS2 на **Linux x64** или Windows x64.
- **Metamod:Source 2.0 не старше сборки от 8 сентября 2026** (с KHook, plugin API 18).
  Проверьте командой `meta version`. Если Metamod старее, плагин не загрузится.
  Обновите Metamod со страницы сборок https://www.sourcemm.net/downloads.php?branch=dev.
- Процессор с AVX (для VPS проверьте, что AVX проброшен в виртуальную машину).

## Установка на Linux-сервер

1. Скачайте архив `cs2glaz-<версия>-linux-x86_64.zip`. Пока нет релиза, его можно взять из
   [GitHub Actions](https://github.com/glazki2/cs2antiwh/actions) этого репозитория:
   последний успешный запуск `build` → артефакт `cs2glaz-linux-x86_64` (нужно войти в
   GitHub). Внутри артефакта лежит сам zip.
2. Распакуйте zip прямо в папку `game/csgo` сервера. В архиве лежат папки `addons`,
   `cfg` и `tools`, их не нужно переставлять.
3. Права на запуск `game/csgo/tools/cs2glaz_baker` плагин выставит сам. Если хостинг это
   запрещает, `cs2glaz_status` покажет `baker missing execute permission`: тогда поставьте
   права 755 через SFTP-клиент (например, WinSCP) или `chmod +x`.
4. Запустите сервер и загрузите карту.
5. В консоли сервера выполните:
   ```
   meta list
   cs2glaz_status
   ```
   В `meta list` должен быть `CS2GLAZ`. В `cs2glaz_status` на актуальном CS2 ожидается строка
   `Game build: unverified; limited mode (walls, hull-shaped body)` и строка `Smoke: ...`.

При первой загрузке карты плагин в фоне готовит «запечённую» копию стен карты. Статус в
это время — `automatic bake in progress`, и все игроки видны. Бейк обычно занимает от
нескольких секунд до минуты. Готовые файлы лежат в `addons/cs2glaz/data/maps/`.

Пустой сервер CS2 засыпает (`Server is hibernating`) и не крутит игровые кадры. Защита при
этом включится, как только зайдёт первый игрок; `cs2glaz_status` тоже доводит подготовку до
конца. Чтобы сервер не засыпал, добавьте в `cfg/server.cfg` строку `sv_hibernate_when_empty 0`.

Вручную карту можно подготовить так (из папки `game/csgo`):
```
./tools/cs2glaz_baker --game ../.. --map de_dust2 --output addons/cs2glaz/data/maps/de_dust2.bvh8
```

## Основные настройки (`cfg/cs2glaz.cfg`)

| Переменная | По умолчанию | Что делает |
| --- | ---: | --- |
| `cs2glaz_enable` | `1` | Главный выключатель |
| `cs2glaz_limited_mode` | `1` | Разрешить защиту стенами на непроверенной сборке CS2 (действует со следующей карты) |
| `cs2glaz_filter_teammates` | `0` | Прятать и тиммейтов тоже. В FFA (`mp_teammates_are_enemies 1`) все считаются врагами автоматически |
| `cs2glaz_visibility_hold_ms` | `150` | Сколько миллисекунд держать игрока видимым после того, как его перестало быть видно (против мерцания). Меньше — враг быстрее пропадает с ВХ, когда уходит за укрытие; было `300`, раньше `1000` |
| `cs2glaz_result_wait_ms` | `3` | Сколько миллисекунд `CheckTransmit` ждёт расчёт видимости этого тика, а не берёт прошлый: враг прячется и появляется на тик (15,6 мс) раньше. Ждёт, только если прошлый расчёт уложился в это время; `0` — не ждать (было). В `cs2glaz_metrics` строка `same-tick results` |
| `cs2glaz_shoulder_base_units` | `48` | На сколько юнитов «выглядывают плечи» зрителя, когда он двигается вбок (против появления врага из воздуха за углом). У стоящего игрока плечи считаются по физике разгона и пингу (около 17 юнитов при 77 мс), но не больше половины этого значения. Больше — враг за углом раскрывается раньше, в том числе для ВХ; было `64` |
| `cs2glaz_shoulder_rtt_scale` | `0.4` | Дополнительный запас на пинг, юнитов на миллисекунду; было `0.64` |
| `cs2glaz_max_shoulder_units` | `128` | Потолок «плеч» при большом пинге; `0` — без потолка (было) |
| `cs2glaz_bounds_padding_units` | `16` | Наибольший запас рамки врага (раскрывает его чуть раньше, чем он выйдет из-за угла). Запас растёт только в сторону, куда враг бежит или жмёт клавиши; стоящему — 4 юнита. Больше — враг за углом раскрывается раньше, в том числе для ВХ; было `32` во все стороны |
| `cs2glaz_worker_threads` | `2` | Потоки расчёта видимости (1–4), действует со следующей карты |
| `cs2glaz_auto_update` | `0` | Автообновление из релизов этого репозитория |

После правки файла выполните `cs2glaz_reload`. Последняя строка `cs2glaz_config_loaded` в
файле обязательна.

Команды — в разделе [«Команды»](#команды) ниже.

## Проверка на своём сервере

Из облачной среды разработки я не мог запустить CS2, поэтому поведение в игре нужно
проверить у вас. Боты годятся как враги, которых прячет плагин, но смотреть должен живой
игрок: боты не получают сетевые пакеты, и клиентские краши на них не воспроизводятся.
Для наблюдения за тиммейтом и проверок с пингом нужен второй живой игрок.

**Загрузка**
- [ ] `meta list` показывает CS2GLAZ, в консоли нет ошибок при загрузке.
- [ ] `cs2glaz_status` показывает `Game build: … limited mode`, а после бейка — `Protection: walls=on`.
- [ ] `meta unload` / `meta load` плагина посреди раунда: сервер не падает.
- [ ] `changelevel` 5–10 раз подряд, в том числе во время бейка.

**Краши клиента (главное)**
- [ ] Спрятанный враг умирает рядом с вами: от пули, ножа, HE, молотова, падения, бомбы, `kill`.
- [ ] Спрятанный враг выходит с сервера или его кикают.
- [ ] Спрятанный враг бросает гранату, подбирает или выбрасывает оружие, несёт бомбу.
- [ ] Вас убивают из-за стены (прострел), камера смерти смотрит на убийцу.
- [ ] Наблюдение за тиммейтом после смерти, быстрое переключение целей, свободная камера.
- [ ] `tv_enable 1` и запись демо, потом просмотр демо.

**Геймплей**
- [ ] Враг за стеной не виден с ВХ (проверять с альта!), но появляется вовремя при выходе
      из-за угла (нет «появления из воздуха»). `cs2glaz_why` в этот момент объясняет решение.
- [ ] Проверка с пингом 80–150 мс.
- [ ] Карты: Dust II, Mirage, Inferno, Nuke, Ancient, Anubis + одна workshop-карта.

**Производительность**
- [ ] `cs2glaz_metrics` на полном сервере: время `transmit` и `worker p99`.

Если что-то пойдёт не так, пришлите вывод `cs2glaz_status`, `cs2glaz_metrics`, `meta version`,
кусок лога сервера и описание того, что делали игроки.

## Команды

Все команды вводятся **в консоли сервера** (RCON), не игрока.

- `cs2glaz_status` — кратко: работает ли защита, карта, режим, производительность.
- `cs2glaz_metrics` — все технические счётчики (время `transmit`, `worker p99`, радар и т. д.).
- `cs2glaz_reload` — перечитать `cfg/cs2glaz.cfg`.
- `cs2glaz_check_config` — проверить настройки, ничего не меняя.
- `cs2glaz_check_update` — проверить обновление сейчас (нужно `cs2glaz_auto_update 1`).
- `cs2glaz_help` — список команд.
- `cs2glaz_status` также показывает приманки: `decoys mode=… ready|unavailable live=… aims=… shots=…`.
- `cs2glaz_why [ник|слот]` — по каждому врагу: расстояние, открыта ли линия видимости и откуда
  (`body`/`bounds corner`/`muzzle`/`hold`; `from eye / left shoulder / right shoulder / above head /
  feet / movement`), и получает ли игрок врага. Вводить в момент, когда ВХ показывает врага.
- `cs2glaz_props [радиус]` — твёрдые предметы рядом с игроками и отметка `[occluder]`, если
  предмет закрывает обзор.
- `cs2glaz_entity N` — что за сущность с номером `N` и когда плагин забирал её у клиента каждого
  игрока или отдавал обратно (через сколько миллисекунд). Нужна после вылета клиента с
  `CopyExistingEntity: missing client entity N`: вводить на сервере **до смены карты** (номера на
  новой карте означают другие сущности). Подробнее — в разделе «Если у игрока вылетела игра».

Переключатели (сбрасываются при перезапуске сервера):

- `cs2glaz_radar_filter 0|1|2` — `0` — радар как в CS2, `1` — враг на радаре, только пока его
  видит кто-то из команды (по умолчанию), `2` — только пока его видит сам игрок.
- `cs2glaz_filter_dead 1` — мёртвые получают только тех врагов, кого видят живые союзники, и
  того, за кем наблюдают. Работает при `mp_forcecamera` 1 или 2; первые 2 секунды после смерти —
  без фильтра.
- `cs2glaz_filter_full_updates 1` — прятать врагов и при «полном обновлении» клиента.
- `cs2glaz_dynamic_occluders 1` — двери и ящики-сущности закрывают обзор, как стены.
- `cs2glaz_decoys 0|1|2|3` — приманки (экспериментально, по умолчанию `0`, см. ниже): `1` —
  невидимые для всех, `2` — нарисованные (только для проверки), `3` — невидимые и **только для
  игроков под наблюдением** (детекты CSVILKA или `cs2glaz_suspect`). Можно прописать в
  `cfg/cs2glaz.cfg`, тогда включаются при каждом запуске.
- `cs2glaz_decoy_kick N` — кикать игрока, когда его улика по приманкам дошла до `N`; `0` — только
  лог (по умолчанию).
- `cs2glaz_decoy_phantoms N` — фантомы: «игроки» без клиента и без слота, с ником спрятанного
  врага, только для одного игрока (экспериментально, риск падений, по умолчанию `0`, см. «Фантомы»).
- `cs2glaz_decoy_front 0|1|2` — невидимая приманка перед прицелом каждого игрока против аимбота;
  `2` — ещё и против триггербота (экспериментально, по умолчанию `0`, см. «Приманка перед
  прицелом»).
- `cs2glaz_decoy_ghosts 0|1|2` — призраки: фейковые игроки, которых видит только «их» игрок и
  которых рисует ESP, показывающий только игроков (экспериментально, по умолчанию `0`, см.
  «Призраки»).
- `cs2glaz_suspect [steamid64|слот|часть ника] [минуты]` — поставить игрока под наблюдение: его
  приманки ставятся первыми (по умолчанию на 30 минут, `0` — снять). Без аргументов — список
  наблюдаемых и состояние связи с CSVILKA.

Скрытие делается в `CheckTransmit`: у спрятанного врага (и его оружия/вещей) снимаются биты в
обоих списках отправки, так что сервер вообще не шлёт его клиенту.

Враг, убитый, пока он был спрятан от игрока (например, его снял тиммейт за стеной), остаётся
спрятанным от этого игрока до своего возрождения: тело игрока, которого клиент ни разу не
получал, может уронить клиент (`CopyExistingEntity: missing client entity`; CS2Fixes по той же
причине прячет всех мёртвых). Такое тело игрок не увидит, даже если подойдёт к нему; выпавшее
оружие видно как обычно. Если же игрок этого врага получал (видел его, был мёртв и смотрел без
фильтра, плагин временно отдавал всех), тело остаётся у него как обычно. Уже удержанные тела
остаются скрытыми и после `cs2glaz_enable 0`, до возрождения. Счётчик — `dead_kept_hidden` в
`cs2glaz_metrics`.

## Приманки (экспериментально)

`cs2glaz_decoys 1` — для каждого живого игрока-человека и каждого спрятанного от него врага (до 5
на игрока, то есть на всех врагов в матче 5 на 5) плагин ставит «приманку»: `prop_dynamic` с
моделью этого врага в месте, которое игрок сейчас не видит.

- **Кто получает.** Только этот игрок и только пока поток видимости доказал, что приманку не видно
  ни из одной его точки обзора (глаза, плечи, над головой, ноги, шаг). Все остальные, SourceTV и
  демо сервера её не получают. Как только игрок мог бы её увидеть, настоящий враг выходит на вид,
  игрок умирает или проходит 8–15 секунд — приманка убирается и ставится новая.
- **Двигается как игрок.** Приманка постоит 0,4–2,5 секунды и идёт к соседней точке, где уже
  стояли игроки (64–320 юнитов), со скоростью 130–250 юнитов в секунду, лицом по ходу движения,
  снова стоит, снова идёт. Путь только по прямой без стен и ящиков между точками (на уровне колен
  и груди), с полом под ногами и уклоном, по которому может пройти игрок; конец и середина пути
  скрыты от игрока. Если к приманке подходит настоящий враг ближе 200 юнитов или сам игрок ближе
  128, она убирается.
- **Где.** Только там, где на этой карте уже стояли игроки (на полу, не в стене), за стеной от
  игрока, не ближе 256 и не дальше 2048 юнитов, не ближе 400 юнитов к любому настоящему врагу этого
  игрока (приманка никогда не подсказывает, где враг) и не ближе 96 к любому игроку. Из
  подходящих мест выбирается ближайшее **перед игроком** (в пределах 60° от того, куда он смотрит):
  ВХ рисует только то, что на экране. Если впереди мест нет — просто ближайшее.
- **Только та, что доходит.** Проп за стеной движок отправляет игроку, только пока тот в зоне
  видимости карты (PVS). Приманку, которая 1,5 секунды не доходила до игрока, плагин переставляет
  на другое место (`undelivered=…` в `cs2glaz_status`), а не держит впустую 8–15 секунд.
- **Одни и те же пропы.** Убранная приманка не удаляется, а откладывается (до 16 штук, их не
  получает никто) и потом переставляется на новое место — но не раньше чем через секунду после
  того, как её убрали (с 0.9.1; раньше её могли поставить снова в тот же тик). Новый проп
  создаётся до модели, чтобы у него не было физики, и при этом один раз пишет в консоль
  `prop_dynamic ... has no model name` — это нормально; благодаря повторному использованию таких
  строк немного. `cs2glaz_status` показывает `parked=… created=… reused=…`.
- **Один показ на приманку (с 0.9.1).** Приманка доходит до клиента одним непрерывным куском.
  Если поток видимости на мгновение не успел подтвердить, что она скрыта, уже отправленную
  приманку не забирают (до 250 мс). Когда её всё-таки забирают (её могли увидеть, настоящий враг
  вышел на вид, игрок умер, 250 мс без подтверждения), показ закончен навсегда: приманку
  убирают и ставят новую. Так клиент никогда не получает сущность обратно через долю секунды
  после того, как потерял её, — именно в таком месте движок CS2 сильнее всего рискует разойтись
  с клиентом. `cs2glaz_status`: `runs ended=…` и число тиков, отправленных без свежего
  подтверждения.
- **Честные игроки ничего не замечают.** Нет коллизии, трассировки (пули, нож) её не задевают,
  нет анимации и звуков шагов, нет записи на радаре и крови. У приманки 1 000 000 здоровья: если
  её всё-таки задела пуля или нож (в логе сервера `killed other "prop_dynamic..."` или
  уменьшилось здоровье), плагин сразу выключает приманки до перезагрузки плагина и пишет об этом
  в консоль. В режиме `1` (его и ставьте на боевом сервере) её вообще не рисует игра: ни модели,
  ни тени; данные о ней (позиция, модель) клиент получает, их и читает чит. Режим `2` рисует
  модель (она всё равно за стеной) — только для проверки на своём сервере, как на неё реагирует
  чит; тень у неё выключена (`m_flShadowStrength 0`, если поле есть в схеме).
- **Отметка.** Если игрок полсекунды **ведёт** прицел за приманкой сквозь стену (она идёт или он
  двигается, а прицел поворачивается вместе с ней хотя бы на 3°), или стреляет в неё из
  огнестрела, в консоль сервера и в `addons/cs2glaz/logs/decoys.log` пишется строка с ником,
  SteamID64, расстоянием и счётчиками; итоги — в `cs2glaz_status` (`decoy suspect`).
  Держать угол, через который она прошла, вести прицел поперёк или идти прямо на неё не считается.
  Выстрел проверяется дважды: по взгляду в момент выстрела и по тому, куда попала пуля (событие
  `bullet_impact`). Второе ловит аимбот, который поворачивает только выстрел, а не экран
  («silent aim»); `cs2glaz_status` пишет, работает ли `bullet_impact` на сервере.
- **Что не считается (с 0.8.0).** Чтобы честный игрок не попадал в лог случайно:
  - приманка считается, только пока она **реально доходит** до клиента игрока (движок отправил её
    в этот тик, а не держал вне PVS: что не дошло, того не видит и чит), и только спустя его пинг
    плюс 150 мс после того, как начала доходить (время, чтобы её увидеть и среагировать);
  - если прицел уже стоял на этом месте, когда приманка появилась (заранее наведённый угол), он
    должен сначала уйти с неё и вернуться;
  - прицел или выстрел, который заодно наведён на настоящего игрока — врага (например, на звук
    шагов) или тиммейта, — не считается.
- **Контрольные приманки-двойники.** Каждая третья приманка — контрольная: это такой же проп,
  он так же ставится, ходит, проверяется и попадает или не попадает в PVS игрока, но плагин не
  отдаёт его даже этому игроку, так что его нет ни у одного клиента и его не видит никакой чит.
  Прицел и выстрелы по нему — это то, как часто именно этот игрок случайно целится в такие места
  (заранее наведённые углы, привычные позиции). Они пишутся только в лог (`event=control_aim` /
  `control_shot`) и в `cs2glaz_status`.
- **Время показа.** Плагин считает, сколько секунд каждая приманка была «готова» (дошла до
  клиента или, у двойника, дошла бы, и прошло время на реакцию) — отдельно для настоящих и для
  двойников. Отметки сравниваются в расчёте на это время, а не просто по штукам.
- **Улика.** Ожидаемое число отметок честного игрока = его частота случайных совпадений (по его
  двойникам, а пока их мало — по двойникам всех игроков сервера) × время его настоящих приманок.
  **Улика** = отметки по настоящим приманкам − ожидаемое − три стандартных отклонения (запас на
  случайность). У честного игрока она остаётся 0, сколько бы он ни играл; ВХ видит только
  настоящие приманки, и улика растёт. Пока на сервере мало данных, частота совпадений берётся
  осторожная (одно на 500 секунд приманки). Учёт идёт **по SteamID с момента загрузки
  плагина** — через смены карт и переподключения. В логе у каждой строки есть
  `real_seconds=… control_seconds=… expected=… evidence=…`, в конце карты — строка
  `event=map_summary` по каждому игроку, в `cs2glaz_status` — частота совпадений сервера и до 10
  игроков с наибольшей уликой.
- **Кик.** `cs2glaz_decoy_kick N` (по умолчанию `0` — только лог) кикает игрока, когда его
  **улика** дошла до `N`. Кик идёт командой `kickid` с сообщением
  `Kicked by the server anti-cheat` (о приманках не говорит), в лог пишется строка
  `event=kick`, в `cs2glaz_status` — `kicks=…`. Вернувшийся игрок кикается снова, когда улика
  вырастет ещё на `N`. Отметка — **подозрение, а не доказательство**: начинайте с `3` и больше, а
  лучше сначала неделю посмотрите лог с `0` и демо.
- **Нехватка времени у потока видимости.** Если поток не успел доказать, что приманка скрыта, её
  не считают увиденной. Ещё не отправленную приманку в этот тик не отправляют, а уже отправленную
  держат до 250 мс (см. «Один показ на приманку»).

### Фантомы — призраки без слота (экспериментально, с 0.12.0)

Призрак — это фейковый клиент, и он занимает слот. **Фантом** слот не занимает: это контроллер
игрока без клиента, созданный в слоте сущностей **выше лимита игроков**. При `-maxplayers 32`
слоты сущностей 33–64 игрокам никогда не выдаются, а внешний ESP перебирает все 1–64 и найдёт
фантома. Его «пешка» — проп-приманка с моделью спрятанного врага, здоровьем 100 и его командой.
Контроллер несёт **ник этого врага** (клон).

- **Включение:** `cs2glaz_decoy_phantoms N` (до 32, по умолчанию `0`) при включённых приманках.
  Один фантом на игрока, сначала подозреваемым (при `cs2glaz_decoys 3` — только им). Нужен
  `-maxplayers` меньше 64 (у тебя 32 — подходит).
- **Кто видит.** Контроллер — только его игрок, тело — только пока стоит вместо его приманки.
  Ходит, прыгает и ловит прицел/выстрелы так же, как приманка.
- **Игра его не замечает.** Нет клиента — нет слота, раунда, спавна, бомбы, событий, килфида,
  записи в списке серверов. Если фантом нужно «переодеть» в другого врага, создаётся новый.
  Рестарт раунда убирает его тело — тогда убирается и он, позже создаётся заново.
- **Риск — самый высокий во всём плагине.** Игра не рассчитана на контроллер без клиента.
  Может случиться всё: от того, что ESP его не покажет, до падения сервера или игры у того
  игрока, кому он отправлен (его клиент получает «игрока», чья пешка — проп). **Проверяй только
  на тестовом сервере и со своими клиентами.** При любом сбое создания фантомы выключаются до
  перезагрузки плагина, причина — в консоли (`phantoms turned off: …`).
- Если у игрока уже есть свободный призрак, используется призрак; фантом — когда призрака нет.
- **Статус:** `cs2glaz_status` — строки `phantom players: …` и `phantom entity N …`.
- **Проверка:** `cs2glaz_decoys 2; cs2glaz_decoy_ghosts 0; cs2glaz_decoy_phantoms 1`, зайти с альта
  с ESP, отойти от ботов за стену: ESP должен показать «врага» с ником бота там, где его нет.

### Приманка перед прицелом — против аимбота и триггербота (экспериментально, с 0.13.0)

Каждому живому игроку ставится **невидимый фантом** (см. «Фантомы»): «враг» с ником и моделью
настоящего врага стоит **в открытую, в 3–20° от прицела**, в 160–1200 юнитах, на полу, где
раньше стояли игроки, без стены между глазами игрока и его телом. Его получает только этот игрок,
только пока жив. Он не рисуется, не отбрасывает тень, сквозь него проходят пули и игроки, и он не
стоит рядом с игроками (и с самим игроком — не ближе 128 юнитов) или на одной линии с ними.

- **Как ломает аимбот.** Аимбот обычно выбирает врага, ближайшего к прицелу, — и это фантом. Каждые
  1,3–3,3 секунды и сразу, как только прицел задержался на нём 0,3 секунды, фантом перепрыгивает
  в другое место на 12–50° по экрану. Аимбот тащит прицел за ним, а не к настоящим врагам.
  Если игрок отвернулся больше чем на 35°, фантом снова встаёт перед прицелом.
- **Как ловит.** Каждый прыжок — проверка, как у «Прыжка приманки»: прицел попал на новое место
  не раньше чем через 120 мс и задержался там 150 мс — это `event=front_jump` в логе. Выстрел,
  линия которого прошла через фантома, — `event=front_shot`. Рядом всегда есть **контрольный
  двойник без сущности**: он ставится и прыгает по тем же правилам, но его нет ни у кого. Его
  отметки (`control_front_jump`, `control_front_shot`) — случайные совпадения честного игрока.
  Улика считается отдельно от приманок за стенами (своя частота совпадений), потом они
  складываются. Кик, CSVILKA и `cs2glaz_status` берут сумму.
- **Против триггербота — `cs2glaz_decoy_front 2` (с 0.13.1, самое непроверенное).** Обычный
  триггербот стреляет, когда «враг под прицелом» из самой игры (`m_iIDEntIndex`) — эту цель
  считает трассировка **клиента**. В режиме `2` телу фантома даётся **коллизия настоящего
  игрока** (копия с пешки живого врага). Тело получает только «его» игрок, поэтому только его
  клиент считает фантома телом игрока. Триггербот стреляет в пустоту каждый раз, когда прицел
  проходит через фантома, и выдаёт себя звуком выстрела. Каждый такой выстрел — `front_shot`,
  его сравнивают с двойником. У **сервера** физического тела у фантома нет (он создан до модели),
  поэтому пули сервера — а попадания решает сервер — проходят сквозь него.
  - **Защита:** если пуля на сервере всё же остановилась внутри фантома (выше колен, где на карте
    ничего нет), режим `2` **сразу выключается** до перезагрузки плагина, а все такие фантомы
    заменяются обычными. В консоли будет
    `front decoys against triggerbots turned off: a bullet stopped…`. Режим требует события
    `bullet_impact` и сам выключается, если коллизия игрока выглядит странно.
  - Фантом в этом режиме держится не ближе 128 юнитов к игроку, чтобы тот в него не упёрся.
  - **Неизвестно без проверки:** находит ли трассировка клиента такое тело и что видит честный
    игрок, когда его пули проходят через фантома (следы, кровь при предсказании попаданий). Это
    нужно проверить на тестовом сервере (см. «Проверка»).
- **Чего он не может.** Аимбот, который проверяет поле, которое есть только у настоящей пешки, или
  чит, научившийся узнавать фантомов, его пропустят. В режиме `1` триггербот из самой игры на него
  не сработает (попадёт только тот, что сам считает по костям, и автоматический выстрел
  аимбота).
- **Включение:** `cs2glaz_decoys 1` (или `3` — только для игроков под наблюдением),
  `cs2glaz_decoy_phantoms 32` (не меньше числа игроков) и `cs2glaz_decoy_front 1` (или `2`). Пока
  включено, все фантомы стоят перед прицелом. Приманки за стенами тогда — пропы (или призраки).
- **При `cs2glaz_decoys 2`** (модели рисуются, для проверки) фантом прыгает, но **ничего не
  засчитывается**: честный тестер, который видит модель и смотрит на неё, не получит отметок и
  кика. Переключение `2` ↔ `1` сразу пересоздаёт фантомы.
- **Риск** — тот же, что у фантомов, и выше, потому что фантом отправляется игроку всё время, пока
  тот жив. **Проверяй только на тестовом сервере со своими клиентами.**
- **Проверка:**
  1. `cs2glaz_decoys 2; cs2glaz_decoy_phantoms 4; cs2glaz_decoy_front 1`, `bot_add_t`, зайти за
     CT. В режиме `2` фантом рисуется: видно, где он стоит и как прыгает.
  2. `cs2glaz_decoys 1`: перед тобой не должно быть видно **ничего** — ни модели, ни тени, ни
     следов пуль в воздухе. Пройди сквозь место, где он стоял, и постреляй туда.
  3. С альта с читом (VAC-риск: только альт): ESP должен показывать «врага» перед прицелом, а
     аимбот — тянуть к нему. В логе должны появиться `event=front_jump`.
  4. Триггербот: `cs2glaz_decoy_front 2`, снова сначала с `cs2glaz_decoys 2`. С альта с
     триггерботом (из игры, `m_iIDEntIndex`) веди прицел через нарисованного фантома: стреляет ли
     триггербот? Потом `cs2glaz_decoys 1` — должны появиться `event=front_shot`.
  5. Режим `2` с **честного** клиента: пройди к месту фантома (не должно тормозить или дёргать),
     постреляй через него (не должно быть крови, следов или звука попадания в воздухе), посмотри
     на него (не должно появляться ника). В консоли сервера не должно быть
     `front decoys against triggerbots turned off`. Если что-то из этого есть — оставь
     `cs2glaz_decoy_front 1` и пришли мне что увидел.
- **Статус:** `cs2glaz_status` — строка `front decoys: …` (сколько работает, прыжков, отметок у
  настоящих и у двойников, частота совпадений честного игрока), при режиме `2` — строка
  `front decoys against triggerbots: …` (включено ли, сколько тел с коллизией создано); в строках
  `decoy suspect` — отметки по фантомам перед прицелом. В консоль отметки по фантомам пишутся не
  чаще раза в 5 секунд на игрока, в лог — все.

### Прыжок приманки (с 0.11.0)

Каждая приманка (и проп, и призрак, и контрольный двойник) один раз за жизнь «прыгает»: когда она
уже секунду дошла до клиента, её мгновенно переставляют в другое скрытое место на 12–50° в
стороне (с точки зрения игрока) и не двигают ещё ~1–1,5 секунды. Честный игрок не видит ни
старого, ни нового места. С ВХ коробка на экране прыгает, и прицел за ней перескакивает. Если
прицел не стоял на новом месте и попал на него не раньше чем через 120 мс (время реакции) и не
позже чем через 0,9 с, и задержался там 150 мс, — это отметка «проследил прыжок»
(`event=jump` в логе). Она идёт в ту же улику, что прицел и выстрелы; двойники прыгают так же,
поэтому случайные совпадения честных игроков учтены. `cs2glaz_status`: `decoy jumps=… followed=…`.

### Попадания по невидимым (с 0.11.0)

Плагин помнит, когда пешка каждого врага в последний раз уходила каждому игроку. Если игрок
попал из огнестрела во врага, которого плагин не отправлял ему уже 1,5 секунды (враг за стеной или
в смоке), — это «попадание вслепую» (`event=blind_hit`). У честных игроков они тоже бывают:
прострел смока, прострел известной точки, наводка тиммейта. Поэтому у каждого игрока доля таких
попаданий сравнивается с долей по всему серверу (как улика приманок: ожидаемое + 3 отклонения).
Это **слабая** улика, но она ловит то, что не закрывает скрытие: **звуковой ESP и радар-хак**.
Когда улика доходит до целого числа, игрок автоматически ставится под наблюдение на 30 минут:
его приманки и призраки идут первыми. Сам по себе этот метод не кикает. Работает при включённых
приманках; `cs2glaz_status` — строки `blind hits since load…` и `blind-hit suspect…`.

### Призраки — приманки, которые видит ESP «только игроки» (экспериментально, с 0.10.0)

Почти все читы, и особенно внешние ESP, рисуют только игроков: перебирают контроллеры в слотах
1–64 и берут их пешки (`m_hPlayerPawn`). Проп-приманки среди них нет, поэтому такой чит её не
покажет никогда. **Призрак** — это фейковый игрок (бот без мозгов), которого получает только
один игрок, и его пешка стоит вместо одной из приманок этого игрока.

- **Включение:** `cs2glaz_decoy_ghosts 1` (или `2`) при включённых приманках (`cs2glaz_decoys 1`,
  `2` или `3`). Призраков не больше одного на каждую команду. Сначала призрак достаётся игрокам
  под наблюдением (детекты CSVILKA, `cs2glaz_suspect`), при `cs2glaz_decoys 3` — только им.
- **Кто его видит.** Призрак заходит за команду врагов своего игрока, и всё о нём (контроллер,
  пешка, оружие) уходит только этому игроку. Остальные его не получают: его нет у них в TAB, на
  радаре, в килфиде; игровые события о нём (зашёл, сменил команду, умер) клиентам не рассылаются.
- **Как ловит.** Пешка призрака стоит за стеной вместо одной из приманок и ходит так же; прицел и
  выстрелы по нему считаются как по приманке (те же правила, та же улика). ESP рисует его как
  обычного врага — с ником, коробкой и скелетом.
- **Безвреден на сервере.** Не получает урона, не твёрдый, пули и нож проходят сквозь него, сам
  не двигается. Если ему выдали бомбу, он сразу её выбрасывает на спавне. Как только в его
  команде больше никто не жив, он убивает себя, чтобы не затягивать раунд. Мёртвых, которые
  наблюдают за ним, переключает на другого игрока.
- **Цена.** Занимает слот (на сервере должно быть минимум 2 свободных места; в списке серверов
  на одного бота больше). Его игрок видит в TAB и в верхней панели на одного врага больше —
  внимательный читер может заметить. Боты CS2 могут стрелять в него (урона нет). Если призрак
  не может зайти за команду (например, `mp_limitteams`) или получил урон, плагин его выкидывает и
  выключает призраков до перезагрузки плагина, причину пишет в консоль. Если призрака выкинула
  сама игра или другой плагин, через несколько секунд создаётся новый; после трёх таких раз
  призраки выключаются. Если призрак не смог выбросить бомбу за 2 секунды, он выходит с сервера
  (бомба при этом падает) и позже создаётся заново.
- **Статус:** `cs2glaz_status`, строки `ghost players: …` и `ghost "имя" slot … viewer …`.
- **Проверка на своём сервере:** `cs2glaz_decoys 2; cs2glaz_decoy_ghosts 1`, зайти с альта с
  ESP за CT или T, отойти от врагов за стену и посмотреть, рисует ли ESP «лишнего» врага за
  стеной. Если что-то пошло не так — пришлите строки `[CS2GLAZ] ghost…` из лога.

Что важно знать:

- Большинство читов рисуют только игроков (контроллер → пешка), а приманка — это проп. Покажет
  ли её конкретный чит, заранее неизвестно; проверяйте с альта: `cs2glaz_decoys 2`, потом `1`.
  Для таких читов есть призраки (см. выше).
- **Почему приманка не притворяется пешкой игрока.** Сервер собирает одну сетевую копию каждой
  сущности на тик, общую для всех клиентов, и отправляет клиенту только разницу с тем, что тот
  уже получил. Плагин может решить лишь, уйдёт ли сущность этому игроку (снять бит), но не может
  послать одному игроку другие значения: подменить `m_hPlayerPawn` контроллера или позицию пешки
  для одного получателя — значит переписывать снимок этого клиента внутри движка. Стоит серверу
  и клиенту хоть раз разойтись в том, что у клиента есть, и следующая разница ломает клиента —
  это тот же вылет `CopyExistingEntity: missing client entity`, что был в 0.7.0–0.7.1, только у
  всех игроков сразу и после любого обновления CS2. Другие пути тоже не годятся: бот виден в
  таблице счёта и считается в раунде, а пешка без контроллера (`player` без игрока) не проверена
  на сервере (риск падения) и всё равно не видна читам, которые идут от контроллеров. Поэтому
  приманка остаётся пропом: её показывают читы, рисующие модели или все сущности, а читы
  «только игроки» её не увидят.
- Проп CS2 отправляет игроку, только пока тот в зоне видимости карты (PVS) этого пропа, а
  приманка стоит за стенами. Если движок не включил её в список игрока, плагин не может её
  добавить: добавление чужой сущности роняет клиента (`CopyExistingEntity: missing client
  entity`, было в 0.7.0–0.7.1). Сколько раз приманка реально ушла игроку и сколько раз была вне
  PVS, показывает `cs2glaz_status` (строка `decoy transmit ticks: sent=… outside_pvs=…`).
- Функции сервера для создания сущностей на неизвестной сборке CS2 ищутся по байтовым шаблонам
  из `addons/cs2glaz/gamedata/cs2glaz.signatures.txt` (взяты из gamedata CounterStrikeSharp).
  Если какой-то шаблон не найден или найден дважды, приманки остаются выключенными
  (`cs2glaz_status` пишет причину), а защита стенами работает как обычно. После обновления CS2
  замените строки в этом файле на свежие из gamedata CounterStrikeSharp и выполните
  `meta reload cs2glaz`.
- Если созданная приманка оказалась твёрдой или видимой, плагин сразу её удаляет и выключает
  приманки до перезагрузки плагина.

## Если у игрока вылетела игра

Сообщение `FATAL ERROR: CopyExistingEntity: missing client entity N` значит, что сервер прислал
изменения сущности `N`, а у клиента её нет. Сервер видит такой вылет как обрыв связи через
10–15 секунд (`NETWORK_DISCONNECT_TIMEDOUT`).

- При таком обрыве плагин сам печатает в консоль сервера, что он забирал у этого игрока и что
  отдавал обратно за последнюю минуту (по строке на сущность, новые сверху): номер, класс,
  причину (спрятанный враг, его оружие, приманка, контрольная приманка, отложенная приманка) и
  через сколько миллисекунд её вернули. Найдите там `#N` из сообщения об ошибке.
- `cs2glaz_entity N` на сервере (до смены карты) — что за сущность `N` сейчас и вся её история по
  всем игрокам.
- `cs2glaz_metrics` — строка `sent again within 300 ms`: сколько раз за карту плагин отдавал
  клиенту сущность меньше чем через 300 мс после того, как забрал (отдельно игроки, их вещи,
  приманки).

Пришлите эти строки вместе с дампом — по ним видно, связан ли вылет с плагином. Пока причина
не найдена точно, держите приманки выключенными (`cs2glaz_decoys 0`) на сервере с живыми
игроками: все три известных дампа с этой ошибкой получены с включёнными приманками.

## Связка с CSVILKA

[CSVILKA](https://github.com/glazki2/CS2VILKA) — серверный античит (аим, движение, клиентские
проверки, подтверждения и наказания). Если на сервере стоят оба плагина, они находят друг
друга через Metamod сами, в любом порядке загрузки, и помогают друг другу:

- **Приманки → CSVILKA.** Каждый раз, когда улика игрока по приманкам вырастает на целое число
  (1, 2, 3…), CS2GLAZ передаёт её в CSVILKA как детект `ESP` с подробностями (сколько раз вёл
  прицел и стрелял по настоящим приманкам, сколько по контрольным, ожидаемое и улика). Дальше
  решает CSVILKA по своим правилам: журнал, Discord, наблюдение, белый список, сетевое вето,
  подтверждение другими детектами и его команда бана. По умолчанию `ESP` в CSVILKA
  экспериментальный (только отчёт), см. README CSVILKA. В логе приманок — строка
  `event=reported_to_csvilka`.
- **CSVILKA → приманки.** На любой детект CSVILKA (AIMBOT, TRIGGERBOT, WALLHACK…, даже
  неподтверждённый) и на найденную историю банов Steam игрок попадает **под наблюдение** на
  окно подтверждений CSVILKA (по умолчанию 30 минут): его приманки создаются первыми и
  подбираются каждый тик, а не раз в 250 мс. В режиме `cs2glaz_decoys 3` приманки получают
  только наблюдаемые игроки — меньше сущностей и нагрузки на сервер, а приманки там, где они
  нужнее всего.
- **Белый список.** Игрока из `csvilka_whitelist` не кикает и `cs2glaz_decoy_kick`.
- Связь видна в `cs2glaz_status` (строка `CSVILKA: connected …`, список наблюдаемых) и в
  `csvilka_status` (`CS2GLAZ bridge: …`); `csvilka_evidence <steamid64>` показывает и улику
  приманок.

Если CSVILKA нет, CS2GLAZ работает как раньше. С CSVILKA рекомендуется оставить
`cs2glaz_decoy_kick 0` и наказывать через CSVILKA: у него подтверждения, наблюдение и сетевое
вето.

### Сверка нового читателя карт (необязательно)

Новый C++-читатель проверен на тестовых файлах ValveResourceFormat: 181 из 181 блока KV3 и
9 из 9 моделей совпали с результатом VRF. Сверить его на настоящих картах можно так: один
раз экспортируйте физику карты любым инструментом в GLB и запустите бейкер с
`--compare-glb путь/к/world_physics_physics.glb`. Бейкер остановится с ошибкой, если число
треугольников или группы поверхностей разойдутся.

## Ограничения

- Звуки шагов и выстрелов не скрываются, так что «sound ESP» остаётся.
- Врага, которого видит кто-то из твоей команды, радар показывает всей команде, как и в
  обычной CS2. Чит может нарисовать его по этим данным, но это те же сведения, что и на радаре.
- Двери и ящики-сущности закрывают обзор (упрощённой рамкой); разрушаемые объекты и прочие движущиеся пропсы — нет.
- Враги у самой кромки видимости передаются заранее (запас на пинг и выглядывание).
- В ограниченном режиме смок прячет только после проверки его смещений на живом смоке; если проверка не прошла, за смоком враг виден.
- Аимбот по видимым целям плагин не ловит. Для этого нужен поведенческий античит.
- Работает только на community/выделенных серверах с Metamod, не в матчмейкинге.

## Сборка из исходников

Linux, внутри Steam Runtime 3 (так же собирает CI):
```
bash scripts/build-linux.sh
```
Windows (Visual Studio 2022, Python 3.8+):
```
.\scripts\build-windows.ps1
```
Скрипты сами скачивают закреплённые версии Metamod, HL2SDK и AMBuild, собирают плагин,
бейкер и тесты, прогоняют тесты и кладут zip в `packages/`. Устройство кода описано в
[docs/CODE_TOUR.md](docs/CODE_TOUR.md) (на английском).
